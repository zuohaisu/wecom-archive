Each file under `routers/` defines a FastAPI `APIRouter()` instance that is mounted by the application root. Routes are split by domain: `auth.py` handles WeCom OAuth flow and password fallback login; `conversations.py` aggregates raw archive messages into Conversation objects with heavy business logic (media access, nested media, revocation handling) and delegates listing to `app.services.listing_service`; `messages.py` exposes both HTML admin pages and JSON APIs; `search.py` implements contact/message search with SQL-level filtering; `reachability_audit.py` wraps `app.reachability_audit` classification logic; `web.py` renders server-side HTML templates for the console UI; `wecom_events.py` validates and decrypts WeCom webhook callbacks. Shared response models live in `schemas/` (`listing.py`, `messages.py`) as Pydantic `BaseModel` classes with `from_attributes=True` for direct ORM mapping. Dependency injection uses FastAPI's `Depends(get_db)` for SQLAlchemy sessions and `get_current_user` / `require_html_session` from `app.auth` for tenant-scoped authorization — tenant_id is never accepted from request parameters, always derived from the authenticated session.
