The application is assembled in `main.py`, which creates a single FastAPI instance, mounts `/web/static` for versioned admin assets, registers all route groups (auth, conversations, messages, search, reachability audit, web templates, WeCom event callbacks), and applies cross-cutting middleware (`MediaAccessNoStoreMiddleware`). Routers depend on shared services from `services/`, ORM models and sessions from `db/`, and WeCom integration via `sdk/wecom_sdk.py` plus `wecom_contacts.py`. The `media_pipeline` (download, classification, thumbnails, storage) is invoked by message/conversation routers. Health endpoints (`/health/live`, `/health/ready`, `/health`) gate deployment readiness against DB schema state via `db.schema_check.full_readiness_check`. All children communicate through FastAPI request/response boundaries and shared Python modules — there is no inter-process messaging.
