This leaf module groups several independent but closely coupled cross-cutting concerns:
- `services/listing_service.py` is a pure service layer that replaces inline logic in `app.routers.conversations`, exposing `list_monitored_accounts`, `list_contacts`, and `list_conversations`. It uses compact SQLAlchemy projections (`_compact_entity_messages`, `_fetch_compact_messages_for_entity`) to avoid full ORM materialization and delegates conversation-key derivation to shared functions from `app.conversation_membership`.
- `message_type_registry.py` is the single source of truth for every WeCom msgtype: it defines enums (`MessageCategory`, `MessageSupportStatus`, `MediaCapability`, `ParserStrategy`, `RendererStrategy`) and a frozen `MessageTypeDefinition` dataclass, then builds an immutable `MESSAGE_TYPE_REGISTRY` mapping raw_type+aliases to definitions. It exposes `resolve()`, `describe_message_type()`, `build_support_matrix()`, and `build_frontend_registry_entries()` so both Python and the embedded frontend share one catalog.
- `structured_message_parser.py` implements the per-msgtype field extractors referenced by the registry's `ParserStrategy` entries (link, location, markdown, news, weapp, vote, todo, collect, meeting, schedule, redpacket, switch_corp, sys, card, audio_archive variants, mixed/chatrecord nested recursion). Every parser returns `(fields, warnings)` and never raises — malformed input degrades gracefully.
- `display_names.py` provides deterministic fallback display names for persons and rooms when real metadata is unavailable.
- `html_helpers.py` offers safe HTML escaping and Beijing-time formatting for admin-only rendering.
- `i18n_assets.py` reads `assets/i18n.js` at import time and exposes `I18N_JS_SOURCE` / `I18N_SCRIPT_TAG` so login and review console embed the same locale registry without duplication.
- `revoke_reconciliation.py` handles idempotent linking of `msgtype="revoke"` events to their original messages via `MessageRevocation`, using SAVEPOINTs and conditional SQL UPDATEs for concurrency safety.
Dependency direction: services depend on models + display_names; structured parsers depend only on the registry; i18n_assets depends only on the filesystem; revoke_reconciliation depends only on db models. No circular imports exist within this scope.
