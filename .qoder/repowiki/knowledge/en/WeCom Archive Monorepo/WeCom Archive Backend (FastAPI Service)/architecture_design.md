The `app/main.py` FastAPI application is the sole process entry point: it mounts static assets under `/web/static`, registers routers for auth, conversations, messages, reachability audit, search, WeCom event callbacks, and the web console, and installs cross-cutting middleware. All HTTP routes share a dependency chain — `get_db`/`get_engine` from `app.db.session` provide SQLAlchemy sessions scoped by tenant extracted from the authenticated session (`app.auth.get_current_user`). The database layer (`app.db.models`, `app.db.base`) is versioned through Alembic migrations in `alembic/versions/`. Cross-cutting concerns (display-name resolution, i18n asset injection, message-type registry) live in `shared_utils` and are consumed uniformly by both API routes and HTML template renderers. Operational scripts under `scripts/` reuse the same DB session factory and models to perform one-off backfills and data migrations, ensuring runtime and offline tooling stay consistent with the shared schema.
