The `backend/` package centers on a single FastAPI application bootstrapped in `app/main.py`, which registers all HTTP routers (`auth`, `conversations`, `messages`, `media`, `search`, `reachability_audit`, `wecom_events`, `web`) and mounts versioned static assets under `/web/static`. All layers share `app/db/models.py` as the single source of truth for persistence contracts: routers call `services/` or domain modules (`media_storage.py`, `wecom_contacts.py`, `structured_message_parser.py`, etc.), which query through the shared SQLAlchemy session. `alembic/` owns versioned DDL evolution against PostgreSQL independently of the app process, driven by `alembic.ini`. `scripts/` provides idempotent one-shot utilities that import directly from `app.db.models` to backfill or migrate data without going through HTTP. `tests/` constructs a test FastAPI client and uses a test-scoped database session mirroring the production setup, ensuring end-to-end coverage across routers, media backends, and migration correctness. Health endpoints (`/health/live`, `/health/ready`, `/health`) gate deploys by checking DB connectivity and schema alignment via `full_readiness_check`.
