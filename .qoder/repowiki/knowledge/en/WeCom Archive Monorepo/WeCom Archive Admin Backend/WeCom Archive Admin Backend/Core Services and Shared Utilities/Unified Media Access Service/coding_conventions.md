- Authorization always completes fully before any storage provider, URL construction, or signing operation is touched — every media route calls `resolve_authorized_media` first, then `_resolve_servable_backend_and_ref`, then either `serve_media_bytes` or `build_access_descriptor`.
- All HTTP error responses use a consistent status-code taxonomy: 404 for not-found/malformed/unservable, 500 for misconfiguration, 503 for provider unavailability, and 502 for confirmed provider-operation failures, raised via `HTTPException` with a short `detail` string.
- Nested media paths are validated strictly against a compiled regex (`^\d{1,6}(?:\.\d{1,6}){0,8}$`) with explicit length and segment-count guards, and resolved only by exact-string equality against precomputed `media_refs` entries — no eval, tree walking, or filesystem mapping.
- Tenant isolation is enforced at two independent layers: the message must belong to the conversation per `_fetch_conversation_messages`, and the `MediaFile` query additionally filters by `tenant_id` so a row can never be served on id alone even if tenant assignment diverges.
- Cloud-backed rows generate signed URLs with a fixed-window deadline via `compute_signed_url_deadline` so the URL is byte-identical across requests within the same window, enabling browser HTTP cache reuse (RND-207).
- Sensitive identifiers (`sdkfileid`, `local_path`, `storage_ref`, `oss_key`) and raw provider error details are never included in HTTP responses or log lines — only safe, sanitized messages are emitted.
