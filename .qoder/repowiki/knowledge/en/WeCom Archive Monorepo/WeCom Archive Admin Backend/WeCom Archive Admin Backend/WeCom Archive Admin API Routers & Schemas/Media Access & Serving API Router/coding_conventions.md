- Every route validates `conversation_type` against the literal set `('direct', 'group')` and raises `HTTPException(400, ...)` for invalid values, rather than using Pydantic validators.
- Routes resolve entity context by calling `_resolve_entity_context(mode, staff_id, contact_id)` and pass the resulting `entity_id` into `resolve_authorized_media`, keeping the authorization boundary identical across top-level and nested media endpoints.
- Each route follows a fixed three-step pattern after auth: call `resolve_authorized_media`, then `_resolve_servable_backend_and_ref(media_file, '<route_label>')`, then `_resolve_variant_serve_ref(media_file, variant, effective_ref)` before either serving bytes or building an access descriptor.
- Access-descriptor routes set `response.headers['Cache-Control'] = 'no-store'` directly on the injected `Response` parameter as a defense-in-depth complement to the middleware, ensuring the header is present even when the success path returns a Pydantic model.
- All storage-provider calls are invoked through `app.services.media_access` helpers with a `route_label` string passed for logging, and raw provider identifiers (sdkfileid, local_path, storage_ref, oss_key) are never returned in responses or logged.
