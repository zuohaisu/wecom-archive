Each file under `routers/` defines a standalone FastAPI `APIRouter()` instance (exposed as `router`) mounted at the application root by the parent app. Routers are split by domain: `auth.py` handles WeCom OAuth plus password fallback login; `conversations.py` aggregates raw archive messages into Conversation objects delegating to `app.services.listing_service` and `app.services.timeline_service`; `messages.py` serves both HTML admin pages and JSON APIs for message browsing; `search.py` implements contact/message search with SQL-level filtering via SQLAlchemy constructs; `reachability_audit.py` wraps `app.reachability_audit` classification behind a read-only admin endpoint; `web.py` renders server-side Jinja templates for the console UI; `wecom_events.py` validates signatures and decrypts AES-CBC payloads from WeCom webhooks; `media.py` centralizes byte-serving and signed-URL descriptor generation, delegating authorization and provider resolution to `app.services.media_access`. Shared response models live in `schemas/` (`listing.py`, `messages.py`, `timeline.py`, `media.py`) as Pydantic v2 `BaseModel` classes with `model_config = {'from_attributes': True}` for direct ORM-to-JSON serialization. Dependency injection uses FastAPI's `Depends(get_db)` for SQLAlchemy sessions and `get_current_user` / `require_html_session` from `app.auth` for tenant-scoped authorization — `tenant_id` is never accepted from request parameters but always derived from the authenticated session.
