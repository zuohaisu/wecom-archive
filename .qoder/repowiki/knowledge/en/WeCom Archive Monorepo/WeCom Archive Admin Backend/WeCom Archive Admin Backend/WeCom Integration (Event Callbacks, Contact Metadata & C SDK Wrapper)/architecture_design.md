Three cooperating layers form the integration:
- `routers/wecom_events.py` exposes FastAPI endpoints (`/api/wecom/archive/events` GET/POST) that validate WeCom signatures (SHA1 of sorted token/timestamp/nonce/payload), decrypt echostr via AES-CBC with PKCS#7 padding, parse the WeCom plaintext envelope, and optionally verify corp_id from env vars. The POST handler currently only validates signatures; actual archive-worker triggering is deferred to RND-107.
- `wecom_contacts.py` provides two read-only httpx clients (`fetch_member_display_name`, `fetch_external_contact_display_name`) against WeCom OpenAPI endpoints (`user/get`, `externalcontact/get`) that return `None` on any failure rather than raising, treating missing metadata as expected.
- `sdk/wecom_sdk.py` is a minimal ctypes wrapper over the compiled WeCom Conversation Archive C SDK, exposing functions for SDK lifecycle (`NewSdk`/`Init`/`DestroySdk`), chat data retrieval (`GetChatData` + `Slice_t` buffers), decryption (`DecryptData`), and chunked media download (`MediaData_t` family with `iter_media_chunks` generator). Each feature group is configured via a dedicated `configure_sdk_*` function that sets `argtypes`/`restype` so missing symbols are caught at configure time rather than at call time.

Dependency direction: routers depend on nothing in this module; consumers of this module call into `wecom_contacts` and `wecom_sdk` directly. All secrets (callback token, AES key, corp_id) come from environment variables and are never logged.
