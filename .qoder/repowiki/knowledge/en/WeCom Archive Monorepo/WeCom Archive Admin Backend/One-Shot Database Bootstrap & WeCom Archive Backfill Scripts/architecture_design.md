Each file is a self-contained CLI entry point with no shared runtime — they are never imported by the application. Every script follows an identical pattern: prepend `backend/` to `sys.path` so it can import `app.db.models`, `app.sdk.wecom_sdk`, and `app.revoke_reconciliation`; read required configuration from environment variables via a local `_require_env` helper; create a SQLAlchemy engine from `DATABASE_URL`; open a `Session(engine)` for all DB work; and exit with distinct codes (0 success, 1 failure) after printing `[INFO]`/`[FAIL]`/`[PASS]` lines. Scripts fall into four categories: (1) bootstrap/migration helpers (`bootstrap_default_tenant.py`, `verify_alembic_head.py`) that set up default tenant rows and enforce schema constraints; (2) WeCom SDK one-shot workers (`sync_wecom_archive_once.py`, `backfill_missing_seqs_once.py`, `decrypt_wecom_messages_once.py`, `download_wecom_media_once.py`, `sync_wecom_archive_once.py`) that call the native `libWeWorkFinanceSdk_C.so` through `app.sdk.wecom_sdk`; (3) data-integrity readers (`check_message_revocations_integrity.py`) that perform pure SELECT-only scans against existing tables without touching migrations; (4) dev fixtures (`mock_ingest.py`). There is no package-level API — dependency direction is strictly outward to `app.*` modules only.
