- All storage operations go through the `MediaStorageProvider` ABC — callers never import `qiniu` or touch filesystem paths directly, and providers are selected via `get_media_storage_provider(storage_backend=...)` with per-row resolution to avoid reinterpreting historical rows.
- Errors are classified into a small hierarchy (`MediaObjectNotFound`, `MediaStorageUnavailable`, `MediaStorageConfigurationError`, `MediaStorageOperationError`) that subclasses built-in exceptions so existing `except FileNotFoundError/OSError/ValueError` handlers keep working while new sites can distinguish confirmed-missing from provider-outage from misconfiguration.
- Every function that touches I/O returns a structured result tuple or NamedTuple rather than raising on normal failure paths — e.g. `classify_media` returns `MediaClassification`, `download_one` returns `(outcome, detail, file_size)`, `generate_thumbnail` returns `Optional[ThumbnailResult]` — failures are encoded in status fields, not exceptions.
- Tenant isolation is enforced at every boundary: object keys are built through `build_tenant_media_key` with `_sanitize_key_segment`, signed URLs require `object_key_tenant_prefix_matches`, and all DB queries filter by `tenant_id` on both `ArchiveMessage` and `MediaFile` sides.
- Byte content is never trusted from metadata — media type detection uses `detect_media_signature_from_bytes` (magic-byte headers) and extension allow-lists (`_ALLOWED_IMAGE_CONTENT_TYPES`, etc.) are consulted instead of trusting `msgtype`, `sdkfileid`, or caller-supplied extensions.
- Environment configuration is read fresh on each call via dedicated accessor functions (e.g. `get_signed_url_ttl_seconds`, `thumbnails_enabled`, `_max_edge`) rather than module-level cached globals, so tests can monkeypatch `os.environ` per case without restart.
