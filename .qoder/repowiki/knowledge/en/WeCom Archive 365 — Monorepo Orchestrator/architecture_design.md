The repository is organized as a flat monorepo where each child module owns its own code, tests, and tooling, while the root `Makefile` provides cross-cutting entry points: `lint`, `typecheck`, `build`, `test`, `verify` for the backend; `ssl-lint`, `ssl-test`, `ssl-dry-run`, `ssl-verify-systemd` for the SSL renewal tool; and composite targets that chain them. All Python tooling shares a single repo-root `.venv` (via `BACKEND_PY = $(CURDIR)/.venv/bin/python`) so ruff, pytest, and runtime dependencies are installed once and reused across backend and SSL-Python checks. The `pyproject.toml` centralizes ruff configuration shared by both children. Deployment is coordinated through `deploy/systemd/` units consumed by the deployment_infra child, which also ships the push-to-deploy script referenced from the README. Secrets flow via `.env.example` templates consumed by every child at runtime, and the root `.gitignore` enforces the no-secrets policy across all modules.
