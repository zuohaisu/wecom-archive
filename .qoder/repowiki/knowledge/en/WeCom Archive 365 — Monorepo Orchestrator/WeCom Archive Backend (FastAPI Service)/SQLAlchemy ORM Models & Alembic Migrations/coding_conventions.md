- Every model class extends the shared `Base` from `app.db.base` and declares its table via `__tablename__` plus a `__table_args__` tuple containing `UniqueConstraint`, `ForeignKeyConstraint`, and named `Index` entries rather than inline column arguments.
- All models include `created_at` and `updated_at` columns using `server_default=func.now()` and `onupdate=func.now()` for automatic timestamp management.
- Tenant isolation is enforced per-row via a `tenant_id` foreign key column on every domain table, with composite unique constraints like `UniqueConstraint('tenant_id', 'wecom_userid', name='uq_contacts_tenant_wecom_userid')` instead of global uniqueness.
- PostgreSQL-specific features (GIN indexes, `postgresql_where` partial indexes, `postgresql_using='gin'`) are declared directly in the model's `__table_args__` so ORM metadata matches the actual schema for Alembic check compatibility.
- Application-level validation beyond DB constraints uses SQLAlchemy `@event.listens_for` hooks (e.g., `_validate_corp_id_on_insert`/`_validate_corp_id_on_update` on `TenantWecomConfig`) to raise typed exceptions before the database constraint fires.
- Migration files follow a strict numeric prefix naming (`0001_initial_schema.py`, `0002_tenant_foundation.py`, …) and each revision sets `revision`, `down_revision`, `branch_labels`, and `depends_on` variables generated from the `script.py.mako` template.
