The FastAPI application in `app/main.py` is the single entry point: it creates the `FastAPI` instance, mounts `/web/static` for the admin UI, registers all routers (`auth`, `conversations`, `reachability_audit`, `search`, `wecom_events`), and installs cross-cutting middleware (`MediaAccessNoStoreMiddleware`). All HTTP routes share a common dependency chain — `get_db`/`get_engine` from `app.db.session` provide SQLAlchemy sessions, while `app.auth.get_current_user` enforces session-based tenant scoping on every request. The database layer (`app.db.models`, `app.db.base`) is versioned through Alembic (`alembic.ini` + `alembic/versions/`), and readiness/liveness endpoints (`/health/live`, `/health/ready`, `/health`) call `full_readiness_check` against the engine to prevent serving before migrations are applied. Cross-cutting concerns (display-name resolution, i18n asset injection, message-type registry) live in `shared_utils` and are consumed uniformly by both API routes and HTML template renderers. Operational scripts under `scripts/` reuse the same DB session factory and models to perform one-off backfills and migrations.
