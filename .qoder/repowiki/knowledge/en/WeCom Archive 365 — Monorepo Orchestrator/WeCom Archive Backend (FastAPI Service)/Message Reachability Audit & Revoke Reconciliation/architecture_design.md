Three cohesive files form two related services:
- `reachability_audit.py` is the core engine: `classify_message_reachability()` is a pure decision function over `(decrypt_status, has_sender, has_room, recipient_count, membership_found)`; `build_message_reachability_report()` paginates `ArchiveMessage` rows per tenant, replays the exact `_fetch_conversation_messages` membership check from `app.conversation_membership` (imported at function scope to enforce one-directional dependency), and returns aggregate counts plus an allow-listed `MessageReachabilitySample` payload.
- `routers/reachability_audit.py` exposes a single FastAPI GET `/api/admin/reachability-audit` endpoint that delegates entirely to `build_message_reachability_report`, taking `tenant_id` only from the authenticated admin session — no request-param tenant scoping.
- `revoke_reconciliation.py` provides two entry points (`reconcile_revoke_event` for immediate processing after decrypt, `reconcise_pending_revocations` as a repair scan) that upsert `MessageRevocation` rows and atomically mark originals as revoked via conditional `UPDATE ... WHERE` statements. Both are idempotent and use SAVEPOINTs + `IntegrityError` handling for concurrent writers.

Dependency direction is strictly inward: routers → service modules; reachability_audit imports `conversation_membership` but never the reverse. All DB access goes through SQLAlchemy `Session`; no ORM models are mutated outside these modules except for the narrowly scoped `is_revoked`/`revoked_at` fields on `ArchiveMessage`.
