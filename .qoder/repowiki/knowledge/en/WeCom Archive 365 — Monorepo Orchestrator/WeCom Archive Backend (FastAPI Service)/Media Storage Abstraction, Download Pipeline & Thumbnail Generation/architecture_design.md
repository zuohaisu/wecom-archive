The module is organized around a single abstract contract `MediaStorageProvider` in `media_storage.py`, implemented by `LocalStorageProvider` (filesystem-backed) and `QiniuStorageProvider` (in `qiniu_storage.py`, imported lazily only when `MEDIA_STORAGE_PROVIDER=qiniu_kodo`). Provider selection is resolved per-call: the default write provider comes from `get_media_storage_provider()`, while existing rows are resolved via their own `storage_backend` column through `get_media_storage_provider_for_backend()` — this per-row resolution is what makes switching providers safe for mixed local/Qiniu storage. Key utilities include deterministic key builders (`build_tenant_media_key`, `build_thumbnail_storage_ref`), tenant-prefix validation (`object_key_tenant_prefix_matches`), content-type detection from both extensions and magic bytes, and a tri-state servability predicate (`resolve_image_file_state`, `resolve_downloadable_media_file_state`).

`media_download.py` implements the unified download pipeline: candidate selection queries (`build_candidate_query`, `select_nested_media_candidates` for mixed/chatrecord nested items), atomic `.part`-then-rename writes, byte-signature validation against `_SIGNATURE_CATEGORY_BY_MSGTYPE`, and the `download_one` worker that returns `(outcome, detail, file_size)` without leaking paths or keys.

`media_thumbnails.py` is a pure, failure-isolated PIL-based generator producing JPEG/PNG thumbnails with EXIF orientation, decompression-bomb guards, and animated-GIF first-frame extraction; `thumbnail_pipeline.py` wraps it into idempotent persistence (`generate_and_persist`) that reads from the same provider as the original, co-locates thumbnails under `tenants/{tenant}/thumbnails/`, and records `thumbnail_status`/`thumbnail_error` on the `MediaFile` row.

Dependency direction is one-way: `media_download` and `thumbnail_pipeline` depend on `media_storage`; `qiniu_storage` depends only on the `MediaStorageProvider` ABC; no cross-imports between download/thumbnail modules.
