- All storage operations raise typed exceptions from a small hierarchy (`MediaObjectNotFound`, `MediaStorageUnavailable`, `MediaStorageConfigurationError`, `MediaStorageOperationError`) so callers can distinguish confirmed missing vs. provider outage vs. misconfiguration instead of collapsing everything into a 404.
- Environment variables are read fresh on every call via dedicated accessor functions (e.g. `get_signed_url_ttl_seconds`, `_max_edge`, `thumbnails_enabled`) rather than cached at import time, enabling per-test monkeypatching and runtime config changes.
- Storage references are built deterministically from `(tenant_id, category, identifier)` using `build_tenant_media_key`, ensuring retried downloads overwrite in place rather than accumulating duplicates, and tenant-prefix validation is enforced via `object_key_tenant_prefix_matches`.
- Content type and media type are derived from actual byte signatures (magic bytes via `detect_media_signature_from_bytes` / `detect_image_type_from_bytes`) rather than trusting caller-supplied msgtype/sdkfileid/extension, with allow-listed extensions checked against explicit tables.
- Cloud-provider code is isolated behind lazy imports: `qiniu_storage` is only imported when `qiniu_kodo` is explicitly selected, keeping local-mode startup free of Qiniu dependencies and credentials.
- Failure paths never log raw secrets, paths, or SDK response bodies; diagnostics use short fixed tags (e.g. `'sdk_error'`, `'write_error'`, `'decode_failed'`, `'upload_failed'`) and helper `_sanitized` to strip exception text.
