Four independent, import-time-pure modules under `backend/app/` with no runtime dependencies on DB/network:
- `display_names.py`: pure functions (`resolve_person_display_name`, `resolve_room_display_name`) that guarantee a non-blank label by falling back to a stable suffix of the raw WeCom ID.
- `i18n_assets.py`: reads `assets/i18n.js` once at import time and exposes `I18N_JS_SOURCE` and a pre-wrapped `I18N_SCRIPT_TAG` consumed by both the login page and review console so locale definitions are never duplicated in Python strings.
- `message_type_registry.py`: defines frozen `MessageTypeDefinition` dataclasses plus `MessageCategory`, `MessageSupportStatus`, `ParserStrategy`, `RendererStrategy`, `MediaCapability` enums; builds an immutable `MappingProxyType` registry from `_DEFINITIONS` at import time with duplicate-key detection; exposes `resolve()`, `describe_message_type()`, `build_support_matrix()`, `build_frontend_registry_entries()`, and `build_filterable_type_options()` as the single source of truth for all msgtype metadata.
- `structured_message_parser.py`: implements the per-msgtype field extractors referenced by `ParserStrategy` entries — each is a pure function returning `(fields, warnings)` and never raises, with defensive bounds (`_NEWS_ITEM_CAP`, `_VOTE_ITEM_CAP`, `_MIXED_ITEM_CAP`, `_MIXED_MAX_DEPTH`) protecting against pathological payloads. The module imports only `message_type_registry.ParserStrategy` and `resolve` to dispatch parsing strategy, establishing a one-way dependency: structured parsers depend on the registry, not vice versa.
Dependency direction is strictly inward: parsers → registry; nothing in this scope imports application routers or models.
