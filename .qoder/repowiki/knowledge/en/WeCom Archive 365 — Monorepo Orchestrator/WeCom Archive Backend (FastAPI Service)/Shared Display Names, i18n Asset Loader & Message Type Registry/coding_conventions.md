- Every public resolver/parser returns a non-blank default when input is missing or empty (e.g. `resolve_person_display_name` falls back to `raw_id` or `"Unknown contact"`, `resolve_room_display_name` falls back to `"Group chat · <suffix>"`), never returning None or blank strings.
- All payload-parsing functions follow the `(fields: dict, warnings: list[str])` return signature, degrading malformed input into warnings instead of raising exceptions, so a single bad row cannot crash an entire timeline render.
- New WeCom msgtypes are added by appending a `MessageTypeDefinition` to the `_DEFINITIONS` tuple in `message_type_registry.py` rather than branching logic in consumers; aliases are declared via the `aliases` tuple so both official and variant spellings resolve to the same definition.
- Defensive multi-key candidate lookup is used whenever WeCom field names are unconfirmed (e.g. trying multiple key variants like `image_url`/`pic_url`/`picurl`, or `from`/`fromusername`/`sender`/`fromuser`), never assuming a single canonical key.
- Security-sensitive fields (monetary amounts in redpacket, corpids in switch_corp/card, participant ids in collect/sys) are intentionally excluded from the extracted `fields` dict and preserved only in the raw sub-payload, enforced by explicit comments marking them as security boundaries.
- Constants that bound untrusted input size are defined as module-level `frozenset` or integer caps (`_SAFE_URL_SCHEMES`, `_NEWS_ITEM_CAP=20`, `_MIXED_ITEM_CAP=200`, `_MIXED_MAX_DEPTH=8`) and applied uniformly across all item-list and recursive parsers.
