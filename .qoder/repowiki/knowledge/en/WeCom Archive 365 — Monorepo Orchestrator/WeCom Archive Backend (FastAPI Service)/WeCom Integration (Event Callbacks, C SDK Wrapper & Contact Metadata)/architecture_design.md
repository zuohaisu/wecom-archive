Three cooperating modules form a thin integration layer over WeCom services:
- `routers/wecom_events.py` defines two FastAPI endpoints (`GET/POST /api/wecom/archive/events`) that perform HMAC-SHA1 signature verification, AES-CBC decryption of echostr/XML payloads, and corp_id validation; POST currently only validates signatures and defers worker triggering to RND-107.
- `sdk/wecom_sdk.py` is a ctypes wrapper around the compiled WeCom Conversation Archive C SDK, exposing typed functions for SDK lifecycle (`NewSdk`/`Init`/`DestroySdk`), chat-data retrieval (`GetChatData` + Slice_t buffers), decryption (`DecryptData`), and chunked media download (`iter_media_chunks` over `MediaData_t`). Each C function group is configured via a dedicated `configure_sdk_*` helper that sets `argtypes`/`restype` before use.
- `wecom_contacts.py` provides two synchronous httpx clients against `qyapi.weixin.qq.com` (`user/get`, `externalcontact/get`) that return `None` on any failure, treating missing metadata as expected rather than exceptional.
Dependency direction: routers depend on neither the SDK nor contacts; the SDK is a leaf used by higher-level workers not shown here; contacts are called independently by archive-display logic. All secrets come from environment variables (`WECOM_CALLBACK_TOKEN`, `WECOM_CALLBACK_ENCODING_AES_KEY`, `WECOM_CORP_ID`).
