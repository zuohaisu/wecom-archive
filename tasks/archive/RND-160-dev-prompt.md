## 四、回滚框架（按改动类别）
- **后端代码**（191 主体）：走 `scripts/deploy_server.sh` 的 RND-227 链路——迁移校验 + `/health/ready` 健康门 + 失败自动回滚到 `last_known_good_sha`。开发 agent 只需保证 `make verify` 绿、且变更可被该链路安全发布。
- **systemd 单元 / timer**（192）：改动前 `cp` 保存原 unit 到 `/srv/apps/wecom-archive-365/shared/rollback/<unit>.bak.<date>`；回滚 = 还原 unit + `systemctl daemon-reload` + `restart`。
- **postgres / journald / logrotate / 备份配置**（193，服务器侧）：改动前全文备份原配置；回滚 = 还原 + 重载服务。任何配置改动写入「变更记录表」（见运维手册）。
- **通用**：每项生产配置改动必须有「保存前副本 + 回滚命令 + 验证命令」三件套，缺一则 QA 判 FAIL。

## 五、运维手册交付（父任务验收硬交付）
RND-160 验收要求「2 核 2GB 环境下的运行建议、阈值和运维手册已更新」。交付物建议落点：
- `docs/operations/2c2g-runbook.md`（新建；若 `docs/` 已有运维目录则并入）。内容至少含：
  - 资源预算分配（RAM：OS / PostgreSQL `shared_buffers`+`work_mem` / uvicorn worker / 后台任务 各占多少）；

## 六、Do-No-Harm 验收闸门（每个子任务都要过）
任何子任务的改动，必须验证不影响四条主流程：
- 归档同步（worker）正常写入；
- 消息解密（`decrypt_status`）不退回、不丢；
- 媒体下载（近期 72h / 缩略图）正常落盘且可被前端访问；
- 后台查阅（员工/会话/时间线/搜索）可用且租户隔离不变。
→ 子任务 QA 报告须显式声明四条主流程 PASS，否则父任务不收口。
