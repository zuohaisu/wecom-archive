# RND-408 官网公开售前 AI 客服

## 产品目标
在官网为未购买、未登录的访客提供 AI 售前咨询，回答：
- 当前已发布的产品功能；
- 当前价格、套餐、试用、购买/续费规则；
- 企业微信接入前的准备事项；
- 通用配置与开通流程。

回答必须附产品资料引用；无依据、合同承诺、优惠、退款争议、隐私或高风险问题必须明确转人工，不得编造。

## 必须遵守的边界
- 当前 RND-354 的 `/admin/support` 是登录后租户管理员助手，必须保持原行为不变。
- 售前访客没有 tenant，**绝不能创建或复用“公共 tenant”**。
- 不得读取或查询 `archive_messages`、联系人、媒体、租户配置、诊断工具或任何企业微信会话存档。
- 访客聊天与已购租户 AI 会话必须使用独立的会话、审计、配额和保留策略。
- 不得将内部文档或 `customer` 级文档直接开放给匿名访客；只允许 manifest 中审核通过的 `public` 级知识源。
- 不修改 Nginx、CI/CD 或生产配置；如官网与 API 跨域问题需要基础设施变更，停止并说明所需运维改动。
- 不提交 API Key、模型密钥、真实访客内容或生产数据。

## 实施要求
1. 增加官网可用的公开聊天入口和匿名 API。
   - 使用随机、不包含身份信息的 `visitor_id` / 会话 Cookie；
   - 不要求登录，不调用管理员鉴权；
   - 不接受“附带诊断信息”参数；
   - 不自动收集联系方式；如需转人工，必须由访客主动填写并确认。

2. 扩展知识库治理。
   - 新增 `public` 访问级别；
   - 建立经审核的公开产品资料：功能、价格、套餐规则、试用、开通与基础配置；
   - 价格和规则必须有单一权威来源、版本和更新时间；
   - 资料变更后可通过既有 reindex 流程更新；
   - 不得依赖模型自身知识或抓取不受控网页内容回答“最新价格”。

3. 独立控制公开流量与成本。
   - 增加独立的公开客服开关，例如 `AI_PUBLIC_SUPPORT_ENABLED`，并受总 AI 开关约束；
   - 增加公共每日 Token 总预算及按匿名访客/IP 的限流或预算；
   - 不能复用 `AI_DAILY_TOKEN_BUDGET_PER_TENANT` 作为访客配额；
   - 默认关闭，模型未配置、知识库为空或预算耗尽时 fail closed。

4. 隐私与安全。
   - 提示访客不要输入企业微信聊天记录、密钥或敏感个人信息；
   - 设置独立的公开会话保留期和删除机制；
   - 保持现有引用、提示注入防护、无证据拒答与转人工机制；
   - 增加自动化测试，证明公开路径不会访问存档、租户配置、诊断工具或内部知识源。

## 验收标准
- 未登录访客可在官网打开聊天入口并咨询价格、功能与配置；
- 回答仅引用 approved + public 的资料；
- 未登录访客无法访问 `/admin/support` 或任何租户 AI 会话；
- 公开客服无法读取租户数据、存档数据、内部文档或诊断信息；
- 关闭任一 AI 开关、模型故障、无证据或预算超限时，安全拒答并提供人工渠道；
- 原有登录后 `/admin/support` 的问答、反馈和转人工功能回归通过；
- 包含迁移、配置说明、测试、QA 总结和回滚说明。
