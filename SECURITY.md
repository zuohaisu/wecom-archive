# Security Policy

## Reporting a vulnerability

Do not disclose suspected vulnerabilities in public issues, pull requests, or
discussions. Use the repository’s private vulnerability-reporting channel when
available. If it is not available, contact the Project Maintainers through the
repository and request a private reporting channel.

Include a clear description, affected version or commit, reproduction steps,
and potential impact. Do not include production credentials, private keys, or
personal data in a report.

## Supported versions

Security fixes are made against the current default branch. Operators should
keep deployments updated after reviewing release changes.
