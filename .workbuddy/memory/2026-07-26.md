## 性能优化 RND-240（搜索点击→聊天详情 ~8s）
- 用户实测点击搜索结果到打开聊天详情页约 8 秒。已定位根因：
  - **前端主因**：`backend/app/web/static/console/console-entry.js:404` `focusMessage` 每次点击都无条件重跑 `setMode → 轮询等实体卡片(200ms×40≈8s 兜底 :419) → onEntityClick(重拉整个实体会话列表) → 轮询等会话卡片 → onConvClick`。即使用户已在看该会话也重拉，后端慢时轮询烧到 8s 天花板。
  - **后端次因**：`backend/app/routers/conversations.py:472` `get_conversation_detail` 调 `_fetch_conversation_messages`(`conversation_membership.py:504`)**不带 limit 全量返回会话所有 ArchiveMessage 行**，只为算 `participants`/`decrypted_percent`，大会话秒级。
- 修复两路：A) 前端短路（实体/会话已选中且卡片在 DOM 则跳过整条重链，直接 focusCheckRow/onConvClick）；B) 后端改聚合 SQL（DISTINCT sender + COUNT/SUM(decrypt_status)），抽 `_resolve_conversation_msg_filter` 复用成员判定，不动 `_fetch_conversation_messages` 既有语义（timeline+media 路由共用）。
- 已建 ticket **RND-240**(Todo, p2, 独立非 epic 子) + 两份提示词：`.workbuddy/prompts/rnd-240-execution-prompt.md`、`rnd-240-qa-prompt.md`。未改代码/未 commit。验收目标：RED ~8s → GREEN `/detail`<500ms、前端<1.5s；回归 test_search_*/rnd229/rnd228/http_contract(路由=33)。
