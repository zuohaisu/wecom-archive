# Crowntime WeCom Archive v1.0.0

发布日期：2026-08-07

> 从“把消息拉下来”到“成为一个产品”，v1.0.0 是 Crowntime WeCom
> Archive 第一个具备完整产品闭环的版本。

## 为什么是 1.0

Crowntime WeCom Archive 于 2026 年 6 月 26 日创建。到 1.0 收口前，项目在
43 个自然日、35 个活跃开发日内完成了 363 次提交，提交标题涉及 153 个不同的
RND 编号。

但我们把它称为 1.0，并不是因为提交数量足够多，而是因为产品已经可以向目标用户
作出一个完整、清晰的承诺：

> 一个可以自托管的企业微信会话存档与审阅系统。它能够持续获取并解密会话记录，
> 安全地保存消息和媒体，让授权管理员进行检索、审阅、导出和审计，并提供支撑
> 长期运行所需的权限、配置、健康诊断和运维能力。

从企业微信接入、消息同步和解密，到检索审阅、媒体访问、身份权限、操作审计、
运行诊断、部署维护和组织自助接入，这条产品链路在本版本第一次完整闭合。

## 五个开发阶段

### 1. 让数据真正流动起来（2026-06-26 至 2026-06-29）

项目建立了 FastAPI、PostgreSQL、Alembic 和企业微信 SDK 的基础工程，完成真实
会话存档同步、消息解密与标准化、会话聚合、搜索与详情接口、第一版管理员审阅
控制台、加密回调验证、部署流程以及租户数据基础。

这一阶段证明了最核心的链路：企业微信的数据能够可靠地进入数据库，并被管理员
看到。

### 2. 从技术链路变成可用的审阅工具（2026-07-04 至 2026-07-13）

产品加入管理员登录、联系人和会话名称同步、员工会话审阅、图片与通用媒体、历史
消息加载、自动刷新、中英文界面、消息可达性诊断和更接近企业微信的消息展示。

同时建立多企业架构、统一媒体存储抽象、七牛 Kodo、Signed URL、SSL 自动续签、
媒体迁移以及结构化消息解析能力。系统开始从“保存原始数据”转变为真正可用的
会话审阅工具。

### 3. 补齐完整性，并重建工程地基（2026-07-18 至 2026-07-27）

这一阶段补齐复合消息、撤回消息、富媒体、嵌套媒体、语音、搜索筛选、结果定位和
长会话性能，并逐步覆盖企业微信会话存档的全部消息类型。

项目也主动偿还了快速开发积累的架构成本：管理后台资源被外置和模块化，Router、
Service、Schema、Worker 和配置职责被拆分，引入 App Factory、完整回归测试、
Alembic/schema-drift 部署门禁和自动化架构防退化规则。

这一阶段让产品获得了继续扩展而不失控的能力。

### 4. 从审阅系统走向管理平台（2026-07-28 至 2026-08-02）

新的设计系统和后台页面体系开始落地，产品逐步获得管理员与角色管理、邀请和账号
生命周期、密码找回、RBAC、租户审计、用量和存储计量、媒体管理、导出审批、
数据保留策略、Onboarding、平台管理、配置中心、首次初始化以及敏感配置加密能力。

消息可达性也从一个后台技术问题转变为管理员可以理解的“会话存档健康”，并拥有
持久化检查、自动诊断和异常发现机制。

系统由此不再只是“查看消息的后台”，而成为具备安全、治理和运行能力的管理平台。

### 5. 闭合接入、运行和采用循环（2026-08-03 至 2026-08-07）

企业微信事件回调正式接入归档 Worker，存档和媒体下载转向事件驱动，并保留低频
对账兜底。产品完成扫码登录审批、客户历史昵称、外部联系人事件刷新、企业微信群聊
真实名称、视频号消息、会话性能优化和存档总览。

企业微信第三方授权、自助创建组织和安全 Provisioning 的完成，使产品开始从
“部署后人工配置”走向“用户自助接入”。开源许可、贡献规范、营销网站、在线演示
和品牌视觉也在这一阶段收口。

## v1.0.0 的产品边界

这个版本建立了以下完整闭环：

- 存档闭环：接入、同步、解密、标准化、媒体下载和历史回填；
- 使用闭环：会话审阅、搜索定位、联系人、富媒体、导出与存档总览；
- 治理闭环：身份认证、角色权限、租户隔离、审批、审计和数据保留；
- 运行闭环：迁移、测试门禁、健康检查、异常发现、部署、备份与回滚说明；
- 接入闭环：初始化配置、企业微信授权、组织认领和自助 Provisioning。

1.0 并不意味着没有缺陷，也不意味着所有产品设想都已完成。真实企业微信能力仍然
依赖腾讯提供的专有 SDK 和部署方自己的企业凭据；不同企业环境中的回调、媒体和
权限配置也仍需按部署文档进行验证。

## 阶段留言

最初，我们想解决的是“如何把企业微信会话记录保存下来”。一路走到 1.0，真正建立
起来的是一套围绕可信存档的产品系统：数据要完整，访问要有边界，操作要可追溯，
异常要能被发现，部署之后还要能够长期运行。

因此，v1.0.0 不是开发的终点。它代表 Crowntime WeCom Archive 已经结束了
“证明它能不能被做出来”的阶段，开始进入“如何让它被更多人稳定、长期地使用”的
新阶段。
