# STORY.md — 365企微会话存档 产品介绍（销售对外）

## ① 用户意图对齐

- **目标受众**：潜在企业客户（决策人 / 采购 / 合规负责人），销售对外演示场景。
- **核心目标**：讲完后让客户相信——「企业微信对话必须、也能被合规地存档、检索与审查」，并记住 365企微会话存档是开箱即用的一体化平台，产生预约演示的意愿。
- **PPT 长度**：13 页（封面 + 目录 + 5 章节内容 + 结束页）。Hero 页配额：封面 / 产品定位 / 结束页 = 3 页（≈23%，落在 20–30%）。
- **视觉调性**：科技现代 / 商务可信 / 干净克制 / 蓝青主色（SaaS 气质）。
- **内容边界**：
  - 必讲：为什么需要存档、产品定位、6 大核心能力、关键能力详解（存档/检索/审查控制台）、安全与合规、应用场景、技术架构与部署。
  - 不讲：内部架构源码细节、Linear/RND 研发流程、价格表、未上线功能的具体承诺。
  - 禁碰：政治敏感、夸大监管强制措辞、虚假数据。

## ② 页面布局骨架

- **页面总数与分章**（5 章）：
  - 封面（01）+ 目录（02）
  - 第一章 为什么需要会话存档：03 章节过渡 / 04 痛点（监管+管理盲区）
  - 第二章 产品定位与核心能力：05 产品定位金句 / 06 核心能力总览
  - 第三章 关键能力详解：07 全量合规存档 / 08 毫秒级会话检索 / 09 会话审查控制台
  - 第四章 安全与合规：10 安全与合规能力
  - 第五章 应用场景与部署：11 应用场景 / 12 技术架构与部署 / 13 结束页
- **Hero 页定位**：01 封面（hero）、05 产品定位（hero）、13 结束页（hero）。任意两 Hero 间隔 ≥1 个 supporting。
- **rhythm 曲线**：01 peak→02 valley→03 peak(过渡)→04 valley→05 peak→06 valley→07 valley→08 peak→09 valley→10 valley→11 peak→12 valley→13 peak。连续 valley 最多 2 页（06-07、09-10），无 ≥3 连续 valley。
- **非对称版式预算**：非对称页 = 02/04/06/07/08/09/10/11 = 8 页（62% ≥ 40%）。对称类（cover/section/金句/图表）仅 01/03/05/12/13。
- **对称版式预算**：全篇「N 卡片横排」计 0 页（远低于上限 2）；章节过渡与封面为特殊对称页。
